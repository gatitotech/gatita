API reference

Build against the Gatita API

One OpenAI-compatible endpoint for talking to the Gatita models, plus a REST API for managing keys, usage, and account state. Every call is authenticated with a bearer key issued from the API dashboard.

Base URL https://api.gatita.tech/v1

Quick start

Get a response in under a minute — you only need an API key and a POST request.

  1. Create a key. Open the API dashboard, go to API Keys, and create a key. It will be shown once — store it somewhere safe.
  2. Send a request. POST to /chat/completions with your key in the Authorization header.
  3. Read the reply. The response is OpenAI-compatible — the text is at choices[0].message.content. 
curl https://api.gatita.tech/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer gatita_your_key_here" \
  -d '{
    "model": "gatita-6.7",
    "messages": [
      { "role": "user", "content": "Say hello in one sentence." }
    ]
  }'

Authentication

All API requests require a bearer key. New keys start with gatita_ and are created and managed in the API dashboard. Send them in the Authorization header: 

Authorization: Bearer gatita_your_key_here
Treat keys like passwords. The full key is only shown once at creation. If you lose it, revoke it in the dashboard and create a new one — there is no way to recover it. Keys issued before this change still use the legacy gsk_ prefix and keep working.

The account and chat endpoints (see Account API) use the same bearer scheme with a session token returned by /auth/login instead of an API key.

Models

Pass the model id in the model field of every request. The model you can use depends on your plan.

Model Description
gatita-6.7 Current frontier model. Smartest answers, slowest output.
gatita-6.7-flash Strong performance, with faster answers.
gatita-6.1-flash Legacy model. Fastest and lightest.

Chat completions

POST /chat/completions

Generates a model reply for a conversation. Accepts the standard OpenAI chat request shape — model and messages are required, everything else is optional.

Request body

Field Type Default Description
model string — Required. Model id, e.g. gatita-6.7.
messages array — Required. Conversation history. Each item is { role, content } with role of system, user, or assistant.
temperature number 0.7 Sampling temperature. Lower is more deterministic, higher is more creative.
max_tokens integer — Maximum tokens to generate. Capped by your plan's per-request limit.
stream boolean false When true, the reply is streamed back as server-sent events.

Example request

curl https://api.gatita.tech/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer gatita_your_key_here" \
  -d '{
    "model": "gatita-6.7",
    "messages": [
      { "role": "system", "content": "You are a concise, friendly assistant." },
      { "role": "user", "content": "What is Gatita Labs?" }
    ],
    "temperature": 0.7,
    "max_tokens": 1000,
    "stream": false
  }'

Streaming

Set "stream": true to receive the reply incrementally over server-sent events (SSE), which feels much faster for longer responses. Each event is a data: line containing a partial choices[0].delta.content; the stream ends with data: [DONE].

Streaming request

curl -N https://api.gatita.tech/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer gatita_your_key_here" \
  -d '{
    "model": "gatita-6.7",
    "messages": [
      { "role": "user", "content": "Tell me a short story." }
    ],
    "stream": true
  }'
import json
import requests

url = "https://api.gatita.tech/v1/chat/completions"
headers = {
    "Authorization": "Bearer gatita_your_key_here",
    "Content-Type": "application/json",
}
payload = {
    "model": "gatita-6.7",
    "messages": [{"role": "user", "content": "Tell me a short story."}],
    "stream": True,
}

with requests.post(url, headers=headers, json=payload, stream=True) as response:
    for line in response.iter_lines(decode_unicode=True):
        if not line.startswith("data:"):
            continue
        data = line[len("data:"):].strip()
        if data == "[DONE]":
            break
        chunk = json.loads(data)
        delta = chunk["choices"][0].get("delta", {}).get("content", "")
        if delta:
            print(delta, end="", flush=True)
const response = await fetch("https://api.gatita.tech/v1/chat/completions", {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    Authorization: "Bearer gatita_your_key_here",
  },
  body: JSON.stringify({
    model: "gatita-6.7",
    messages: [{ role: "user", content: "Tell me a short story." }],
    stream: true,
  }),
});

const reader = response.body.getReader();
const decoder = new TextDecoder();
let buffer = "";

while (true) {
  const { done, value } = await reader.read();
  if (done) break;
  buffer += decoder.decode(value, { stream: true });
  const lines = buffer.split("\n");
  buffer = lines.pop();
  for (const line of lines) {
    if (!line.startsWith("data:")) continue;
    const data = line.slice(5).trim();
    if (data === "[DONE]") continue;
    const delta = JSON.parse(data).choices[0].delta.content;
    if (delta) console.log(delta);
  }
}

Errors

Errors use the OpenAI error shape — a non-2xx status with a JSON body of { "error": { "message": "...", "type": "...", "code": ... } }. Always handle the HTTP status, not just message.

Status Meaning
400 Invalid request — malformed JSON, missing model or messages, or an invalid parameter.
401 Missing or invalid API key. Check the Authorization header.
403 Account banned, has active strikes, or the model is restricted for your plan.
404 Unknown endpoint or model id.
429 Rate limit exceeded — per-minute or per-day. Retry after the limit resets.
500 Server error. Retry with backoff, and contact us if it persists. 
{
  "error": {
    "message": "Rate limit exceeded. Please slow down.",
    "type": "rate_limit_error",
    "code": 429
  }
}

Rate limits & plans

Limits are set by your plan and tracked per key. The dashboard's Usage & Limits tab shows your live usage against these numbers.

Plan Requests / day Requests / min Max tokens / request
Free 200 6 4,096
Plus 2,000 30 8,192
Pro 10,000 100 32,768

On 429, back off and retry. The per-day counter resets at midnight UTC; the per-minute counter rolls every 60 seconds.
